# 真机验收清单（15 屏）

手机接 USB 后，一条命令跑完全部拍照（需要 worker 在本机 8789 跑着）：

```powershell
$adb='E:\tools\android-sdk\platform-tools\adb.exe'
& $adb devices                      # 应看到一台 device
& $adb reverse tcp:8789 tcp:8789    # 让手机 127.0.0.1:8789 打到宿主机 worker
& $adb install -r 'E:\DeepSeek workers\otsmail-android\app\build\outputs\apk\debug\app-debug.apk'
& $adb shell am force-stop com.otscup.otsmail
& $adb shell am start -n com.otscup.otsmail/.MainActivity
```

截图规矩：`adb shell screencap -p /sdcard/x.png` + `adb pull`（**不要用 `adb exec-out screencap >`**，PowerShell 会写坏 PNG）。
**返回别用 `keyevent 4`**（会退回桌面），点页面左上 `‹`。

包名 `com.otscup.otsmail`，桌面名「OTSMail 新版」（手机里另一个 8 月的旧包 `com.otsmail.app` 同名，别看错）。

## 已知会在真机上暴露的问题（我改不动，需要真机确认）

1. 详情页正文高度：`WebView` 用 `onPageFinished` 的 `contentHeight`，极短正文可能停在 220dp 兜底；
2. 详情页暗色正文配色（HTML 壳已换成主题色，未在真机暗色下看过）；
3. 1080×2280 与设计稿 393×852 的留白换算（dp 与 pt 近似，但三星的密度 2.625 会放大半像素）；
4. 写信页附件选择、草稿回填；
5. 全部邮件翻页的尾页（`total` 与实际可取数可能不一致，可能多点一次「加载更多」）；
6. 联系人 A–Z 索引的跳转位置。

## 2026-10-31 真机回归结果

- 15 屏全部出图，落在 `F:\Desktop\MFiles\otsmail-android-shots\acc\`；脚本 `tools/cap15.cjs` 每屏冷启动后再进，避免页面栈错乱。
- 本轮修掉的三处：
  1. 抽屉「其他」组（联系人/AI/设置/系统设置）在 1080×2280 上被裁到屏外、完全点不到 —— 抽屉根 `Column` 补 `.verticalScroll(...)`（`7e79820`）；
  2. 启动时 `Session.apply()` 排在 `LaunchedEffect` 里，晚于首屏请求，导致首批接口带着空 token 出去（分析页收件/发件/已删除恒为 0）—— 改成 `remember { Session(context).also { it.apply() } }`（`170fb33`）；
  3. 收件箱时间列用 `takeLast(5)` 取自 `yyyy-MM-dd HH:mm:ss`，拿到的是 `mm:ss`（真机显示 `32:38`）—— 改用 `clockOf()` 取 `HH:mm`。
- 仍未验：长正文/宽表格邮件是否还右裁、暗色正文配色、全部邮件尾页、联系人索引跳转。
