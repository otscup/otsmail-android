# 聚合收件 · 第三批：统一收件箱

范围：把第三方邮箱邮件并入现有收件箱列表，顶部按账户筛选，第三方邮件可点开只读详情。
本批不做写操作（回复/删除/标已读回写 IMAP），不做推送（FCM + IDLE + 去重留到下一批）。

## 2. 合并与排序策略

**内存合并，服务端分页保持原样**——不做「双源分页后再拼」。

原因：服务端每页 20 封，本地第三方是 SQLite。如果两边各自分页再按页拼接，两个游标步长不同（20 vs 60），滚到底会出现「这一页的第三方邮件比下一页的服务端邮件还新」的错位，而且无法在不重排已渲染区域的前提下修正。

实际做法（`InboxMerge.merge`）：

1. 服务端当前已加载的 1..N 页（`MailCache` 原有逻辑）作为 server 行，key `s:<emailId>`。
2. 第三方取本地库，key `x:<extId>:<localId>`，按时间倒序，附加 **时间下界**：
   - 服务端还有下一页时，下界 = 已加载最旧一封的时间，只补「这个时间及更新」的第三方邮件；
   - 服务端全部加载完后，下界放开，整个本地库参与合并。
3. 合并后统一按时间倒序排序，时间相同按插入顺序（服务端在前）保持稳定。

排序时间口径：服务端 `yyyy-MM-dd HH:mm:ss`（UTC 语义）与第三方 `epoch ms` 都由 `TimeFmt.epochMs` 转成毫秒再比；解析失败的脏数据沿用更旧一封的时间，不会乱插。

**不乱序、不重复的保证**：

- 新翻一页只会让下界变旧 → 新出现的第三方行**一定比当前已显示的所有行都旧**，只会追加在列表尾部，已看到的位置不跳。
- 本地分页扩大同理，只在尾部追加更旧的行。
- 两类 key 前缀不同，且本地 `(ext_id, message_id)` 唯一、服务端 `email_id` 唯一，不存在同一封邮件出现两次。

## 3. 分页处理

| 来源 | 分页方式 | 触底行为 |
| --- | --- | --- |
| otsmail（服务端） | 原有 `MailCache` 20 封/页 + `loadMore()` | 保持原逻辑；第三方筛选激活时不再触发（避免白拉） |
| 第三方（本地） | 本地页 60 封（全部视图 200 起，每页 +80） | 距底部 4 行时 `extPage++` 重新查库，最多 40 页兜底 |
| 全部视图 | 两者同时参与 | 服务端翻页先推进下界，本地页兜底超过窗口的深库存 |

滚动位置：合并列表的 LazyColumn key 是字符串（`s:` / `x:`）。刷新后按「刷新前可见行 key」在旧合并列表里找回扁平索引（`flatIndexOfRows`），找不到才回顶，不会因插入第三方行把位置打乱。选择态、滑动操作仍只针对服务端邮件行。

## 4. 顶部账户筛选

位置：搜索框下方一行横向滚动的 chips，只在存在已绑定第三方账户时出现。

| chip | 服务端来源 | 第三方来源 |
| --- | --- | --- |
| 全部 | 当前收件箱范围（沿用原逻辑） | 所有已绑定账户 |
| 当前 otsmail 地址（`session.email`） | 当前账号 | 不显示 |
| 每个第三方邮箱地址 | 不显示 | 仅该账户 |

切换即时生效（纯本地状态，不重新请求服务端）；所筛账户被解绑时自动退回「全部」。关键词搜索：服务端仍走接口搜索；第三方在本地按主题/发件人/地址/摘要/正文过滤，两者合并展示。

## 5. 失败与空态（非弹窗）

- **同步失败横条**：列表上方一行浅底提示，列出失败账户地址与本地记录的原因（如「认证失败（授权码错误或已失效）」「连不上收件服务器」），右侧「重试」触发一轮同步。不弹窗、不遮挡列表。
- **第三方空态**：只筛某个第三方邮箱且本地没有邮件时，显示「这个邮箱还没有邮件 / 同步失败」+ 具体原因 + 「立即同步」按钮。
- **otsmail 空态**：沿用原有各文件夹空态文案。
- 失败原因本地与服务端各存一份；本轮同步成功后客户端顺手清掉服务端旧错误，避免横条一直挂着。

## 6. 列表行与详情

列表行：直接复用 `OTMailRow`，与现有邮件同一个组件、同一套排版：

- 未读：`![FLAGS \Seen]` → 未读点/加粗；
- 时间：`TimeFmt.rowTime`，日期分组头 `TimeFmt.dayLabel` 同一口径；
- 发件人姓名优先，空则地址；主题空显示「（无主题）」；摘要来自解析结果；
- 星标：渲染未标星状态，点击提示「第三方邮箱，本轮暂不支持写操作」（不静默成功）；
- 附件标记：摘要行末尾回形针（`hasAttachment`），现有 otsmail 行不受影响；
- 行内小字标注该邮件所属的第三方邮箱地址，避免和 otsmail 混淆。

详情：`ExtMailDetailScreen`，按本地 `local_id` 取邮件。

- 正文 HTML 优先、纯文本兜底（`pre` 保留换行）；
- 清洗沿用 `sanitizeEmailHtml`，图片沿用 `InlineImages` 代取（带 UA/Referer、拦内网、失败回透明图），与普通详情同一条链路；
- 顶部提示条为「第三方邮箱，本轮暂不支持写操作」，**不是**之前的「全站只读」文案；
- 附件只显示文件名与体积，注明「暂不支持下载（已保存在服务端归档）」；
- 打开详情不改已读状态（不回写 IMAP），列表未读态与邮箱真实状态保持一致。

## 7. 保持可用

- 搜索：接口搜索与文件夹/全站范围未改；第三方仅参与本地关键词过滤。
- 下拉刷新：仍刷新服务端第一页；同时**并行**触发一轮第三方同步（不受 15 分钟节流限制），不阻塞刷新动画。
- 推送刷新：`PushManager` 与刷新逻辑一行未改。
- 进入收件箱时原有的静默 `ExtSync.maybeSync`（15 分钟节流）保留；同步结束后 `ExtSync.rev` 变化，列表自动重读本地库，不用切页。
