## 版本与发布规则

- 正式版本号只在推送 GitHub 打 tag 时递增；**以 Git tag 为准**（2026-11-09 本地 tag 含 `v0.3.4`）。
- `nextReleaseName` 以 `app/build.gradle.kts` 为准（2026-11-09 为 `"0.3.4"`）；发下一个正式版前推进并打新 tag。
- `versionCode = major*10000 + minor*100 + patch`（只升不降）；本地构建 `<下一个正式版本>-dev.<序号>`，序号存 `.dev-version`（不入库）。
- L9-L15 的 `0.2.5/0.2.6/dev` 装机记录为**历史记录，勿直接复用**；实际被测构建必须标注 commit/tag/是否 dirty。
- 注意：本机 debug 包用 Android Debug 证书，与正式签名包可能冲突；本地装机/发版签名走 `keystore.properties`（不入库）。

## 0.3.1 待办（0.3.0 发布后启动，本文只登记，未开工）

### 0. 待验项与已知缺陷

- 待验：窄屏 360–400dp 下固定宽度表格是否真的自适应。用模拟器或 `adb shell wm size` 把宽度调窄后复验，不能只在大屏上看。
- 已知缺陷：GitHub 通知邮件表头 `Status` 折成 `Sta/tus`，原因是列宽不足，不是右侧裁切；是否在 0.3.1 调整列宽策略待评估。

### 1. 验证码识别与一键复制（优先级最高，不依赖服务端）

- 可行性：可行，纯客户端实现，不需要新增接口。
- 依赖与改动面：
  - 客户端：本地正则识别 4–8 位数字，且上下文命中验证码/校验码/OTP/code 等关键词才展示；详情页识别后直接写剪贴板；验证码弹窗同样写入；通知栏「复制」因 Android 10+ 后台不能直接写剪贴板，需要短暂拉起透明 Activity 写入并提示结果。
  - 服务端：无。网页端：无。
  - 改动点：详情页/弹窗复制入口、通知 action、新增透明 Activity 与 Manifest 声明、正则单测。
- 已知约束：纯本地识别，不上传正文和验证码；正则只做候选提示，金额/订单号等数字需靠上下文关键词排除；透明 Activity 拉起有被系统后台限制拦截的可能，失败要提示「请打开 App 复制」，不能静默。
- 部署阻塞：不会被服务端部署卡住。

### 2. 扫码登录网页端

- 可行性：可行，但要客户端、服务端、网页端三边一起上。
- 依赖与改动面：
  - 网页端：登录页生成一次性票据二维码（60 秒过期），轮询取会话。
  - 服务端：新增票据创建/轮询/确认接口；票据一次性、过期即废；确认时记录并展示设备与浏览器信息。
  - 客户端：扫码页用 ZXing（纯 Java，约 0.5 MB）；不要引入依赖 GMS 的 ML Kit；扫码后用已登录 token 调确认接口。
  - 入口：桌面图标长按出「扫一扫」，用 Android 静态 App Shortcuts（`res/xml/shortcuts.xml` + manifest 的 `<meta-data android:name="android.app.shortcuts">`），快捷方式带深链直接进扫码页，不要先进首页再跳；App 内头像/抽屉菜单放同一项，走同一个深链。未登录时先引导登录，登录后继续扫码，不能直接丢到错误页。
  - 改动点：mail-worker API + D1（或 KV）票据表、mail-vue 登录页、Android 扫码页与相机权限、shortcuts.xml 与深链处理。
- 已知约束：票据必须一次性且过期即废，轮询要有频率上限；确认页要能看到设备与浏览器信息；全程 HTTPS。扫码失败/票据过期要有明确提示。
- 部署阻塞：会被服务端部署卡住（worker 与网页端必须一起发）。

### 3. 网页端查看第三方邮件

- 可行性：只读「已归档内容」成本低、风险可控；「服务端自己主动拉取」受容器/cron 限制，不在 0.3.1 范围。
- 依赖与改动面：
  - 服务端：新增已归档第三方邮件的只读查询接口（`ext_mail` + R2 附件签名地址），按用户鉴权、分页返回。
  - 网页端：新增只读列表/详情入口（第三方邮件标识、附件下载）。
  - 客户端：无改动。
  - 改动点：mail-worker ext API、mail-vue 页面与路由、D1 查询与分页。
- 已知约束：只读，不提供标记已读/星标/删除/回复，避免与 IMAP 上游状态不一致；归档缺失的邮件不承诺可见；不承诺实时性。

1. `adb shell cmd appops get com.otscup.otsmail POST_NOTIFICATION` **先查**：重装/覆盖安装都会把它重置为关闭，不查就会出现「只入库不弹通知」（05:11 那封就是）。

3. `adb shell cmd notification set_dnd off`（仅验证期间，避免系统睡眠勿扰吃掉通知）。
4. `adb install -r -d app-release.apk`（设备已有更高 versionCode 时必须 `-d`，保留数据；签名必须与已装包一致，本机用 `assembleRelease`）。

7. 检查：通知内容正确、同封只有一条、点击进详情、通知上无写操作按钮。
8. 飞行模式 30–60 秒：看 `logcat -s ExtIdle` 必须出现「保留 IDLE 服务」而不是 `onDestroy`；恢复网络后出现「账户对齐（网络恢复）：重建 N 条 IDLE 连接」并重新挂上 IDLE。
